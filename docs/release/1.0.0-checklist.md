# 1.0.0 release checklist (maintainer)

Branch `motion-programmaticlayer` is prepared for `@elah/core`, `@elah/react`, `@elah/timeline` and
`@elah/editor` **1.0.0**. Agents may not run any step below: they install, publish, tag or push.
Work through it in order, on a clean working tree, and stop at the first failure.

`@elah/cli` is **not** part of this lockstep release. It was bumped to its own **1.0.0** on
2026-10-27 (its `@elah/core` range is `^1.0.0`) and is published separately, with the ffmpeg work,
under its own `cli-v1.0.0` tag. `@elah/react-native` is pre-release and unpublished.

## 0. Before you start

- [ ] Read the open items the preparing session reported (the **Result** of
      `docs/tickets/TICKET-CONV-6.md` in the workspace): the bundle-size stop, the `Stability`
      paragraph in the changelog (a recommendation: confirm or edit it), and the `react-native` range
      below.
- [ ] `git status` is clean and the branch is the one you mean to tag. The date in `CHANGELOG.md` and
      `apps/web/config/changelog.ts` is `2026-10-22`: change both if you publish on another day.
- [x] **Bundle size: settled 2026-10-23.** `TICKET-CONV-7` and `TICKET-CONV-8` are done. The
      experimental layers are `@elah/core/spec`, `/html`, `/ops` and `/icons`; effects, generators,
      sequence clips, roto masks and audio Enhance load on first use. The founder accepted the
      editor app at **112 KiB gz** for 1.0 (the 105 KiB target was not met; further trimming of the
      timeline package and video decode path comes after launch). That figure is already in
      `BUNDLE_STRATEGY.md`, the changelog entries, `packages/core/README.md` and the AI guide.
- [ ] Re-run the release gate below on top of CONV-7 and CONV-8. `npm run build --workspace=apps/web`
      has not run since: stop any `next dev` on `apps/web` first (it shares `.next`).

## 1. Refresh the lockfile (before tagging)

```bash
npm install --package-lock-only
```

- [ ] Review `git diff package-lock.json`: the four packages and `@elah/cli`'s `@elah/core` range
      move to 1.0.0, and nothing else churns. Expect the lockfile to be stale today: it still records
      0.6.0.
- [ ] **`packages/react-native/package.json` still declares `"@elah/core": "^0.6.0"` and
      `"@elah/react": "^0.6.0"`.** It was outside this ticket's allowed files. With core at 1.0.0 the
      workspace no longer satisfies that range, so npm may resolve a copy of 0.6.0 from the registry
      into `packages/react-native/node_modules`. Change both ranges to `^1.0.0` **before** running the
      command above, then check `npm ls @elah/core` shows one copy.
- [ ] Commit the lockfile with the version bumps.

## 2. Release gate

```bash
npm run build:packages
npm run typecheck
npm run test
npm run build --workspace=apps/web
npm run lint:tokens
```

- [ ] All exit 0.
- [ ] From `elah-premium-creator`: `node scripts/sync-core-to-oss.mjs ../elah --check` exits 0
      (no core drift: premium is upstream for `packages/core`).
- [ ] `npm pack --dry-run --workspace=packages/core` reports about 1.2 MB packed (1,158,481 bytes when
      this was prepared), 735 files. A much larger number means something unintended went into the
      tarball.

## 3. Tag

- [ ] Tag the commit that carries the refreshed lockfile: `git tag v1.0.0` (the four lockstep
      packages share one tag). The CLI tag, `cli-v<version>`, is for its own release.
- [ ] Push the branch and the tag yourself.

## 4. Publish (one at a time, in this order)

```bash
npm publish --workspace=packages/core     --access public
npm publish --workspace=packages/react    --access public
npm publish --workspace=packages/timeline --access public
npm publish --workspace=packages/editor   --access public
```

- [ ] After each, `npm view @elah/<name>@1.0.0 version` before publishing the next: each depends on
      the ones before it.
- [ ] **Never `npm publish --workspaces`**: no control over order and no pause between packages.
- [ ] Do not publish `@elah/cli` or `@elah/react-native`.

## 5. Verify the published packages

- [ ] **Examples.** `examples/{minimal,next,react}/package.json` still pin `@elah/editor` `^0.6.0`,
      and `verify:examples` only builds (it does not install). In each example set the range to
      `^1.0.0` and run `npm install` there (they are outside the root workspace, with their own
      lockfiles), then from the repo root:

      ```bash
      npm run verify:examples
      ```

      Then update the "verified against" lines in `examples/README.md` and `examples/AGENTS.md`.
- [ ] **CDN check, against the real jsDelivr URL** (the part that CONV-5 could only prove against a
      local stand-in). In a Chromium page on an origin other than jsDelivr:
      1. `import * as elah from 'https://cdn.jsdelivr.net/npm/@elah/core@1.0.0/+esm'` loads
         (about 740 exports).
      2. Build a short title sequence with `TimelineEngine` (text clips in `bebas-neue` and
         `playfair-display`) and call
         `exportVideo(project, { fonts: { baseUrl: elah.packageFontsBaseUrl() } })`
         **without** overriding `window.Worker`: the export must start (a `blob:` module worker that
         imports the worker's `/+esm` build) and produce an MP4 that plays.
      3. The network log shows the woff2 requests under
         `https://cdn.jsdelivr.net/npm/@elah/core@1.0.0/fonts/<id>/…`, and the title is set in the
         real fonts (not a fallback).
      4. Repeat the audio-analysis and capability-probe workers if you use them.
      If step 2 fails on the `/+esm` URL, the unit-tested branch in `utils/workerUrl.ts` needs fixing
      in `elah-premium-creator/packages/core` and a re-sync, then a patch release.
- [ ] A clean `npm install @elah/editor lucide-react` in an empty Vite app typechecks and builds
      (this is also what `verify:examples` does).

## 6. After publishing

- [ ] Create the GitHub release for `v1.0.0` from the `CHANGELOG.md` entry.
- [ ] Deploy `apps/web` so `/changelog`, `/docs/project-documents`, `/docs/api`, `/docs/editor` and
      `/docs/timeline` show 1.0.0. The version badge and the install snippet read `currentVersion`
      from `apps/web/config/changelog.ts`.
- [ ] **Bundle sizes on the site.** The docs quote 112 KiB gz (editor app), 45 (engine), 75 (render +
      export). If any later change moves them, re-run `node scripts/measure-bundle.mjs` and update the
      same places. The README badges were removed and are not restored here.

## Known leftovers, not blocking

- `packages/editor/src/editor/Preview/TransitionOverlay.tsx` is unused (the GPU renderer draws
  transitions). It was left in place; delete it when you review the diff.
- `ARCHITECTURE.md` (§ transitions, the `<Preview>` row) and comments in `packages/core`
  (`resolver/scene.ts`, `types/index.ts`, `export/ExportWorker.ts`) still describe the CSS snapshot
  overlay. The core comments are premium-owned: fix them there and re-sync.
- `apps/web/components/landing/landingData.ts` still has the FAQ "What changed in 0.6.0?".
- `packages/core/THIRD_PARTY_NOTICES.md` (premium-owned) says the fonts are "about 740 KB"; the
  package measures 623,058 bytes.
- `@elah/editor` does not re-export the 1.0.0 programmatic layer (effects, generators, spec, ops,
  `vector/html`, `packageFontsBaseUrl`): consumers import it from `@elah/core`, and spec, ops, html
  and icons from `@elah/core/spec`, `/ops`, `/html` and `/icons`. The docs say so; adding
  re-exports is a code change for a later release.
